# 06 · 本地数据（脱离微信可用）方案

> 需求来源（2026-11-07 用户）：「Tk 版能下载数据到本地，数据管理应该有本地数据选项，
> 这样脱离微信也能用」。本文件是清单方案，落地时按 Phase 推进并回填验收结果。

## 1. 目标与场景

- **导出**一份自包含的本地数据包（HTML 站点 + 附件副本 + 索引状态），
  **任意时刻回读**：浏览/筛选/选择/再导出，全程**不依赖微信进程与密钥**。
- 关键场景：微信未登录、换账号、密钥取不到（真机截图里的
  `KEY_NOT_FOUND / open-process-failed`「在微信进程内存里没找到与本账号数据匹配的密钥」）
  —— 本地数据是这条错误路径的正解。
- 对齐 Tk：导出按钮产出 HTML 站点 + 「打开导出目录」按钮 + 可从导出目录回读
  （`gui.py:141 btn_open`、`gui.py:664 load_from_export_dir`）。

## 2. 现状盘点（数据层 / sidecar / 前端）

| 能力 | 数据层（Tk，只读复用） | sidecar | 前端 |
|---|---|---|---|
| 导出记录 JSON/CSV | ✅ `guidata.write_json/write_csv` | ✅ `export` 方法 | ✅ 按钮齐全 |
| **全量本地数据包**（HTML 站点 + 附件副本 + `.wxchart-state.json` + 导出报告/日志） | ✅ `exporter.export()`（B2 八项测试守护，`export_state` 写 `day_entries`） | ❌ **未暴露** | ❌ 无入口 |
| **从导出目录回读**（不需要微信运行——`guidata.py:7` 注释明说） | ✅ `load_from_export_dir` | ✅ `load_source kind=export`（契约测试 2 项已覆盖） | ❌ **零 UI**（`kind:'export'` 只有类型定义，无人调用） |
| 打开导出目录 | ✅ `os.startfile`（Tk `btn_open`） | — | ⚠️ 有 `reveal_path` 命令但无入口 |
| 导出目录图片预览 | ✅ 附件已复制进数据包 | — | ❌ asset scope 静态配置只放行解码缓存，**未覆盖导出目录** |

**关键结论**：
1. 缺口不在数据层（Tk 能力原样在位、零重写），在 **sidecar 暴露 + 前端 UI** 两层；
2. 现有 JSON/CSV 导出**不写** `.wxchart-state.json` → 产出**不可回读**，不算本地数据包
   （JSON/CSV 保持现状不动，数据包是新增的第四种导出形态）；
3. 懒解码的「导出前补齐未解码图片」（2026-11-07 三轮已做，回写 `raw.media_paths`）
   正好服务数据包的附件复制——`exporter._copy_media` 读的就是 `media_paths`。

## 3. 清单方案

### Phase 1 · 最小闭环（P0，≈1 天）

| # | 项 | 落点 | 要点 |
|---|---|---|---|
| 1 | sidecar 暴露数据包导出 | `sidecar/launcher.py` | `export` 增 `format:"bundle"`（或新方法 `export_bundle`）→ 调 `exporter.export()`；进度回调接现有 `progress` 通知；`EXPORT_TIMEOUT` 900s 已预留（冷缓存全量附件 ≈7min）；产出后把数据包根注册进 PathScope |
| 2 | 「导出本地数据包」入口 | 聊天数据管理页 | 选目录（dialog）→ 全量导出（进度条走 `data://progress`）→ 完成后「打开导出目录」（对齐 Tk `btn_open`，复用 `reveal_path`） |
| 3 | 「打开本地数据」入口 | 聊天数据管理页 | 选目录 → `load_data {kind:"export", out_dir}` → **复用现有全部链路**（虚拟滚动/筛选/选择/引用跳转/导出）；状态行 `来源：导出目录` 已实现无需改 |
| 4 | asset scope 覆盖数据包 | `src-tauri` | 导出/回读成功后 `asset_protocol_scope().allow_directory(数据包根)`（Tauri 运行时 API）→ 数据包内图片缩略图可显示；静态 scope 不动 |
| 5 | 测试 | 三端 | 契约：bundle 形状 / state 可回读 / 附件缺失容错 / 无微信回读；e2e：入口→回读→来源标识；真机：导出 → 退出微信或换账号 → 回读全链路 |

### Phase 3 #14 · 导出设置页（选择性 + 增量数据包）—— 2026-11-10 设计冻结

**差距起因**：用户对照 Tk 版导出页截图（2026-11-10）——新版只有「导出本地数据包」（全量），
**时间范围 / 内容类型 / 生成物勾选 / 会话多选 / 增量导出**均未迁移（增量此前连文档都没记录）。

**底层（零改动复用，`wxchart-tool/` 只读）**：

- `exporter.export(account, store, chats, *, out_dir, start_ts, end_ts, include, html, csv,
  media_index, date_index, incremental, progress, cancel_event)`（`exporter.py:248`；
  Tk `gui.py:480` 同款调用链 = 截图页的参数面）；
- `export_state`：**同目录同账号**增量——跳过无新消息会话、附件同内容（blake2b 比对）复用
  不重复复制、**跨账号混写拒绝**（`exporter.py:300-312`）；`导出报告.json` 带 `mode/new_messages`；
- 图片密钥：`MediaResolver.ensure_image_key` 自动推导（Tk 默认勾选；sidecar 现行 bundle 已挂
  真实 resolver，行为已在位）。

**协议**：docs/02 §1.2 `export` bundle `options`（**已冻结**，形状与白名单校验以 docs/02 为准）。

**UI（建议放「聊天数据管理」页内嵌面板——待拍板①）**，逐项对齐 Tk 截图：

| Tk 截图项 | 新版控件 | 绑定 |
|---|---|---|
| 搜索会话 + 全选/清空/反选 | `chat_tree` 加勾选 + 现有 `entry_search` + 三按钮 | `options.chats`（勾选子集；全选 = 缺省语义） |
| 时间范围 从/到 + 全部/今天/近7天/近30天/本月 | 两个日期输入（复用 DatePicker，A3 已有）+ 快捷按钮组 | `options.start_ts/end_ts`（`YYYY-MM-DD` → ts，同 Tk `_parse_date`） |
| 导出内容：文字（必选禁用）+ 图片/文件/视频/语音 | 复选组，text 恒勾禁用 | `options.include` |
| 生成物：HTML / csv / 按类型索引 / 按日期索引 | 4 复选，默认全勾 | `options.artifacts` |
| 增量导出（跳过没有新消息的会话） | 复选，默认勾（同 Tk `var_incremental(True)`） | `options.incremental` |
| 输出目录 + 浏览 | `pickDir` + 最近目录记忆（`last_export_dir` 复用） | `outPath` |
| 开始导出 / 打开输出目录 | 按钮 + `data://progress`（已有）+ 完成提示 | `export_messages` |

**完成提示**：full → 「已导出数据包 N 条 → 路径」（现行）；incremental →
「增量导出完成：新增 N 条 → 路径」（同 Tk `gui.py:305` 文案，数据取 result `mode/newMessages`）。

**验收（落地时增补进 docs/04）**：

- **契约 +N**：options 逐字段形状 / 未知键 `INTERNAL` / `chats:[]` 与未知会话 id /
  时间倒置 / include 归一恒含 text / 增量 `mode+new_messages` / 跨账号混写拒绝；
- **e2e +N**：设置面板 → `exportMessages` 参数透传（mock 断言）+ 增量完成文案；
- **真机 +1**：同目录二次导出——首跑 full、二跑 incremental（报告 mode、新增条数、
  目录字节数不暴涨 = 附件不重复复制）+ **选择性子集包回读**（`load_source kind=export`）。

**待拍板**：①面板位置（管理页内嵌 vs 新「导出」页签；建议前者——会话树现成）
②图片密钥开关是否进协议（建议暂不进：默认自动推导已是现状）
③「停止导出」本轮不做（协议无 cancel 参数；Tk 有，后补）。

## 4. 验收口径（落地时增补进 docs/04）

- **D 类硬验收**：干净场景（微信退出/未登录）安装版打开数据包 → 浏览、筛选、图片缩略图、
  附件点击打开、再导出 JSON/CSV 全过；
- 契约 +N（bundle 导出与回读）、e2e +N（两个入口）、真机 +1（脱离微信全链路）。

## 5. 风险与边界

- **不改导出格式**（docs/01 非目标）：数据包 = 现有 `exporter.export()` 原样复用，三方格式一致；
- `wxchart-tool` 只读：sidecar 调用即可，数据层零改动；
- 数据包体积 = 附件副本全量（用户自选盘符/目录）；导出期间互斥锁已有（`EXPORTING_BUSY`）；
- 冷缓存首次数据包导出图片解码耗时长 → 900s 超时 + 进度已就位，Phase 1 顺带真机量化一次。
