# 01 · 总体架构与路线（Phase 2A · Tauri）

> 结论先行：**界面与运行时换 WebView2（原生 exe、无 Python），数据层先 sidecar 复用
> 已验证的 Python 实现**；91 项测试按 `docs/04` 的映射迁移为验收清单。

## 1. 目标与非目标

**目标**

1. 交付**单安装包原生 exe**：安装后不依赖本机 Python（M-A4）；最终完全无 Python（M-A5，可选）。
2. 解决 Tk 版的渲染天花板：滚动/重绘交给 Chromium 合成器（60fps、脏区由浏览器管），
   文本选中、`Ctrl+F`、CSS 动画（引用跳转闪烁）全部**白送**。
3. 行为与 Tk 版**逐项对齐**（微信式交互），以 `docs/04` 的 91 项测试为验收契约。
4. 数据层零重写起步：`wxchart-tool/src/wxchart`（解密/解析/筛选/导出，91 项测试守护）
   原样复用，避免"重写引入回归"。

**非目标（本阶段不做）**

- 不重写数据层为 Rust（M-A5 再评估）；
- 不改消息字段 / JSON / CSV 导出格式（与 Tk 版、导出 HTML 三方保持一致）；
- 不做 macOS/Linux 适配（协议与前端天然跨平台，但打包验证只承诺 Windows）；
- 不合并两版代码库：`wxchart-tool` 单独保留、独立演进。

## 2. 架构总览

```
┌────────────────────────── wxchart-tauri.exe（Tauri 2 · Rust 壳） ──────────────────────────┐
│  ┌── 窗口 / 菜单 / 保存对话框 / 路径打开（Tauri plugins: dialog · opener）               │
│  │                                                                                      │
│  │  invoke(cmd) ──────────────► 命令路由（校验参数、路径 scope、协议版本握手）            │
│  │  emit(event) ◄────────────── 进度 / 数据源变更 / sidecar 存活状态                     │
│  └──────────────────────────────┬───────────────────────────────────────────────────────┘
│                                 │ 内部路由（多数命令直通 sidecar）                        │
│  ┌──────────────────────────────▼───────────────────────────────────────────────────────┐
│  │ sidecar 管理：启动 · ping 健康检查 · 崩溃重启一次 · 退出时优雅收尾                      │
│  └──────────────────────────────┬───────────────────────────────────────────────────────┘
└─────────────────────────────────┼────────────────────────────────────────────────────────┘
                                  │ stdin/stdout 换行分隔 JSON（无网络端口）
                                  │
        ┌─────────────────────────▼────────────────────────── wxchart-data.exe ────────────┐
        │  sidecar 启动器（PyInstaller 打包的 Python）                                      │
        │  └─ 复用 ../wxchart-tool/src/wxchart：keys · sqlcipher · model · guidata ·       │
        │     exporter（数据在内存，导出直写文件）                                          │
        └──────────────────────────────────────────────────────────────────────────────────┘

前端（WebView2 · Vue3 + TS + Vite）
  · 全量加载一次（≈11k 条 / 数 MB）→ 客户端筛选、虚拟滚动、引用跳转、选区全在本地
  · ipc/ 适配层双实现：tauri invoke（生产） / 浏览器 mock（Vitest·Playwright 测试）
  · 气泡样式移植 exporter.py 的 HTML/CSS（已经过 14 项 filter_page 测试与真机比对）
```

**关键数据流**：`load_data` 一次性把消息拉进前端内存 → 筛选/分组/选中/引用跳转全部本地
零 IPC 往返（与 Tk 版 `filter_messages`、导出 HTML 单页同构）→ 导出时只把
**选择下标或筛选条件**发回 sidecar，由 sidecar 用自己内存里的同一份数据写文件（数据不出进程）。

## 3. 选型与理由

| 候选 | 结论 | 理由 |
|---|---|---|
| **Tauri 2 + WebView2**（选定） | ✅ | exe 小（~10MB 壳）、WebView2 Win10/11 自带、Rust 侧未来可承接数据层、官方 sidecar 机制正合本项目 |
| Electron | ❌ | 包体 100MB+、内存高；无必要（不需要 Node 运行时能力） |
| PySide6 / Qt | ❌ | 仍是 Python 运行时；视图层同样要重写；依赖变重（前面路线 C 已排除） |
| 纯 Rust GUI（egui/iced/Slint） | ❌（本阶段） | 中文排版/文本选中/虚拟列表全要自拼，开发量最大；留作 M-A5 后的可选项 |
| 继续 Tk 优化 | ❌（已做完） | Phase 1 已把拖动做到 0.87ms/事件；渲染天花板（合成器级重绘）在 Tk 里到顶 |

**前端栈**：Vue 3 + TypeScript + Vite。
- 理由：模板语法对"气泡列表 + 面板"这种结构最直接；TS 契合 IPC 的类型化 payload；
  Vite 开发期可在**普通浏览器**里跑（配 `ipc/` 的 mock 实现），测试与调试都不依赖壳。
- 备选 vanilla TS 也可行（更少依赖），代价是状态同步代码自己写；团队单人开发时 Vue 的
  模板可读性收益更大。状态管理用组合式函数 + reactive store 即可，不引入 Pinia（规模不够）。
- **虚拟列表**：自研 windowing（平铺渲染计划，和 Tk 的 `_plan` 同构：分组头/日期条/时间条/
  消息铺平 → 只渲染可视窗口 ± overscan）——现成虚拟列表对"分组头+日期条+多行气泡"的
  变高行支持都要大量定制，自研反而省。

## 4. 关键设计决策

### D1 · 数据层先 sidecar，不现在用 Rust 重写
Python 数据层（密钥提取、逐页解密、zstd、appmsg/quote 解析、筛选、JSON/CSV）有 31 项
直接测试 + 真机验证，是**已兑现的资产**；现在重写 = 高风险 + 零用户可见收益。
sidecar 把它包成稳定契约（docs/02），M-A5 换 Rust 实现时**前端一行不改**。

### D2 · 全量加载 + 客户端筛选（与 Tk 版同构）
11796 条消息 ≈ 数 MB JSON，invoke 一次拉完（进度用分块 event 上报）。
好处：筛选、分组、引用跳转（按 server_id/内容本地查）、选区全部**零往返**；
导出例外——只回传下标/条件（见 D3）。
代价：切换数据源要重新拉取 → **`load` invoke 返回即刷新**（前端拿到数据直接渲染，
单窗口无后台数据源变更，无需 `data://source-changed` 事件——2026-11-10 #10 裁剪定案，
docs/02 §3 事件表本就没有它）。

### D3 · 导出在 sidecar 侧执行
前端把 `{mode: "selected"|"matched", indexes[] | filter}` 发过去，sidecar 用内存数据
`write_json/write_csv`，返回文件路径 → Tauri dialog 只负责选路径。
理由：数据不来回搬运；导出格式 100% 复用现有实现（CSV 防公式注入、BOM、截断 `…` 等
规则零重写）。

### D4 · 微信式"单气泡选区"天然兼容虚拟滚动
浏览器里**跨虚拟节点的文本选区**是经典难题（滚动后选区断裂）。本项目交互契约本来就是
"选区限单条消息"（与微信一致）→ 选区永远落在一个气泡组件内，DOM 原生 selection 即可，
虚拟化无副作用。跨气泡 = 多选勾选（状态在 store，与 DOM 无关）。
——这是"交互规格复用给 Phase 2 省时间"的最直接例证。

### D5 · 引用跳转 = scrollIntoView + CSS 闪烁
sidecar/前端本地按 `server_id`（导出数据按内容匹配，规则与 Tk 版 `_find_quoted` 相同）
定位目标 → 虚拟列表 `scrollToIndex` → 目标气泡加 `.flash` class（CSS animation 1.4s）。
Tk 版的手写闪烁/坐标换算全部作废。

### D6 · 打包 = Tauri bundle 内嵌 sidecar
sidecar 用 PyInstaller `--onedir` 打成 `wxchart-data-x86_64-pc-windows-msvc.exe`
（Tauri `externalBin` 要求平台后缀），随安装包分发；壳启动时拉起。
详见 docs/03。

## 5. 渲染能力对照（为什么"重绘更强"）

| | Tk Canvas（现状） | WebView2（Phase 2A） |
|---|---|---|
| 滚动 | Tk 逐项重绘 + Python 事件 | 合成器层滚动，独立于 JS 主线程 |
| 文本选中 | 自研：自行换行 + 像素命中 + 高亮矩形（~800 行） | DOM 原生 selection / Ctrl+C / Ctrl+F |
| 重绘触发 | 每个 canvas item 变更 → 脏区重算（Phase1 实测平移 7000 项 102ms） | DOM diff + 浏览器脏区，硬件加速 |
| 动画（引用闪烁） | after 定时器逐帧改画布 | CSS `@keyframes`，主线程零参与 |
| 多选勾选框 | 逐个 create_text + 增量平移（Phase1 优化到 203ms） | 数据驱动渲染，`v-for` + `:class`，随帧更新 |

## 6. 风险与对策

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| R1 | 本机未装 Rust 工具链/MSVC | 无法动工 | ✅ 已解决（M-A1，2026-11-06）：rustup stable 1.99.1（USTC 镜像）+ 复用已有 VS 2026 Build Tools（MSVC 14.50 + SDK 26100），不另装 2022；见 README 环境前提 |
| R2 | PyInstaller side被杀软误报 | 安装/启动被拦 | onedir 而非 onefile、申请代码签名（可选）、安装说明附白名单指引 |
| R3 | sidecar 启动慢（Python 冷启动 0.5–1.5s） | 打开应用有等待 | 壳先出窗口 + 启动骨架屏；`ping` 就绪后 `data://ready` 切换；预热常驻 |
| R4 | 双版本长期并存的维护成本 | bug 修两处 | 冻结 `wxchart-tool` 功能范围（只修不加）；新功能只进 2A；契约测试两边共用 |
| R5 | 虚拟列表 + 变高行的滚动精度 | 跳转/滚动错位 | 平铺计划 + 行高缓存（与 Tk `_plan` 同构）；M-A2 先做滚动专项验收 |
| R6 | WebView2 老机器缺失 / 初始化不稳 | 装完打不开 | Evergreen 引导器随包；✅ **2026-11-07 结案**：不是运行时/GPU/提权问题，而是「工作区被打 Low 完整性标签 → 构建出的 exe 继承 Low IL → WebView2 拒绝初始化」。`scripts/fix-dev-integrity.ps1` 把 `target` 树 IL 改回 Medium 即好（见 docs/05）；打包到安装目录（Medium）不受影响 |
| R7 | invoke 大 payload（全量消息）卡顿 | 首次加载白屏 | 分块 event 上报进度；前端先拿索引再懒取正文（备选，M-A2 视实测决定） |
